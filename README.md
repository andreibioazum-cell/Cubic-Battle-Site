# Cubic Battle 4

Одностраничный сайт игры Cubic Battle 4 с событием «YA — YourAnswer»: модальное окно с формой ника, опросом на время и выдачей эксклюзивного куба. Сборка и сторонние библиотеки не нужны.

## reCAPTCHA

На экране ввода ника, перед кнопкой «Продолжить», показывается компактная reCAPTCHA v2 Checkbox. Перед запуском опроса браузер отправляет ответ на `/api/verify-recaptcha`; серверная функция Vercel проверяет его через Google SiteVerify и дополнительно сверяет hostname. Публичный site key находится в HTML, секретный ключ хранится только в переменных окружения сервера. Тип ключа в консоли reCAPTCHA должен соответствовать v2 Checkbox; для score-based/v3 нужен другой клиентский сценарий.

### Настройка Vercel

1. В настройках проекта Vercel откройте **Settings → Environment Variables** и добавьте `RECAPTCHA_SECRET_KEY` со значением secret key из консоли reCAPTCHA. Выберите нужные среды (Production и, если требуется, Preview), затем выполните redeploy.
2. API-функция `api/verify-recaptcha.js` будет опубликована Vercel как `/api/verify-recaptcha` автоматически.
3. По умолчанию сервер принимает только hostname `cubic-battle-site.vercel.app`. Для дополнительных доменов задайте `RECAPTCHA_ALLOWED_HOSTNAMES` как список через запятую, например `cubic-battle-site.vercel.app,example.com`, и добавьте эти домены в настройки ключа reCAPTCHA.
4. Для локального запуска через Vercel CLI скопируйте `.env.example` в `.env.local`, заполните секрет и задайте `RECAPTCHA_ALLOWED_HOSTNAMES=localhost` (при необходимости добавьте `localhost` в разрешённые домены ключа reCAPTCHA), затем запустите `vercel dev`. Файл `.env.local` исключён из Git. Не добавляйте секрет в HTML, JavaScript, публичные переменные сборки или репозиторий.

При размещении не на Vercel нужен серверный POST-обработчик с такой же проверкой: один статический HTML-сайт не может безопасно использовать secret key.

Интеграция использует классический обмен site key + secret key через SiteVerify. CreateAssessment относится к интеграции reCAPTCHA Enterprise и требует отдельной настройки Google Cloud и серверной аутентификации; одного классического secret key для переключения недостаточно.

**Ограничение текущего сайта:** проверка блокирует обычный пользовательский запуск опроса без CAPTCHA, но сам опрос и сообщение о выдаче куба пока работают на клиенте. Для реальной защиты выдачи игрового предмета сервер должен также проверять результат опроса и вызывать доверенный API игры для начисления награды.

## Структура

```text
index.html                 Разметка и контент страницы, публичный site key
api/
└── verify-recaptcha.js     Серверная проверка токена через SiteVerify (Vercel)
assets/
├── css/
│   ├── base.css            Переменные, базовые стили и типографика
│   ├── layout.css          Сетка страницы и секции (шапка, герой, футер)
│   ├── components.css      Кнопки, карточки, модальное окно и опрос
│   └── responsive.css      Адаптация для телефонов
└── js/
    └── event-quiz.js       Логика события: модалка, таймер, опрос и reCAPTCHA
```

Стили разделены по назначению, JavaScript вынесен из разметки. Из внешних ресурсов используются шрифт Roboto и Google reCAPTCHA.
